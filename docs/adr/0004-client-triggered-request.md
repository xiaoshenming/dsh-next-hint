# AD-0004 判定在浏览器，生成在宿主：一次请求-响应

- 状态：已接受（2026-10），取代 AD-0001 里「宿主订阅轮次事件 + SSE 推送」的通道设计
- 相关：[ARCHITECTURE.md](../ARCHITECTURE.md) `2、`3、[OPEN-QUESTIONS.md](../OPEN-QUESTIONS.md) H1 H3 C1 H4

## 背景

AD-0001 假设链路是「宿主订阅轮次结算 → 生成 → 推到浏览器」。复核 `0.2.1-rc.2` 源码（[RESEARCH.md](../RESEARCH.md) `4.7）后，这个假设多付三笔成本：

1. 宿主「轮次结算」这条缝没核实过（H1），而会话事件里只有 `turn/start`、`turn/end`，语义要自己推断；
2. 推送要 SSE，宿主就得按会话存状态、处理断连重连、缓存失效；
3. 「草稿是否为空、用户是否正在打字、当前看的是哪个会话」**只有浏览器知道** —— 推过去的建议仍要浏览器二次校验，等于两处判定。

浏览器侧本来就握着两样事实：会话运行位（`session.running`）与输入框快照（`draft` / `draftRev` / `phase`）。

## 决策

**判定在浏览器，生成在宿主，一次请求-响应，不用 SSE。**

- 浏览器判定「可以给建议」后发 `POST /api/next-hint`，请求体只有 `{ sessionId, locale }`。
- 宿主按 `sessionId` 自己取上下文（`ctx.sessions.get(id).deriveMessages()`），发一笔辅助请求，`{ hint }` 直接作为响应返回。
- 浏览器拿到结果后再校验一次 `draftRev` 与当前会话，然后渲染。

## 后果

- 好处：宿主半边无状态 —— 无长连接、无会话映射、无失效清理；取消就是 `AbortController.abort()`。
- 好处：会话原文不出进程边界。浏览器只发 id，不把自己渲染的转录再上传一遍。
- 好处：H1、SSE、`src/feed.mjs`、`src/store.mjs` 全部从设计里消失（少三个模块、少一类失效）。
- 代价：多一跳本机往返（可忽略）；只有浏览器在线时才可能出建议（远端/断线时静默，符合「可降级」）。
- 约束：路由只接受同源、loopback 来源；`sessionId` 必须可解析且属当前用户。
- 约束：迟到的结果必须丢弃（比对 `draftRev` 与当前会话 id），否则会插进别的语境。
