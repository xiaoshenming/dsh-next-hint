# 规划

> 兼容基线：DeepSeek Harness `0.2.1-rc.2`（本机实测）
> 状态：**M0 脚手架已落地**，功能未开始

一句话：**一轮对话结束后，输入框里出现一句「接下来可以问什么」，Tab/点击采纳即写入草稿。**

---

## 1. 做

- **建议条**：助手这一轮结束、且草稿为空时，在输入框上方出现一条建议；可点击或按快捷键采纳。
- **可撤销**：采纳等于一次普通文本插入，Ctrl+Z 能撤回，绝不自动发送。
- **生成解耦**：建议由一笔**独立的辅助 LLM 请求**产出，不占用主请求延迟；失败就是没有建议，不打扰对话。
- **可控**：开关、模型路由、输出上限、超时、触发策略（每轮 / 仅空闲 / 手动快捷键）都能配。
- **可降级**：没有可用路由、模型报错、超时、远端浏览器、旧宿主 —— 一律静默降级为「没有建议」。
- **两半都测**：纯逻辑走 `node:test`，浏览器半边有假宿主，宿主半边有假 LLM。

## 2. 明确不做

- 不做第二套补全/菜单引擎 —— `/`、`@` 的候选菜单归 `dsh-client-ui-input-trigger`，我们只在它右侧/上方说一句话。
- 不改官方 React 组件、不 fork 官方包、不 patch `.asar`；只用公开 seam（槽位、服务、路由、DOM 注入）。
- 不把 `@deepseek-ai/*` 写进 `dependencies`（只允许 `peerDependencies`，且默认 optional）。
- 不做对话记忆、RAG、语义索引 —— 建议只看当前会话最近几轮。
- 不做「自动替我发送」「批量追问」这类无人值守行为。
- 不把用户会话原文送到任何第三方服务；只用用户自己配置的模型路由。

## 3. 里程碑

| 阶段 | 内容 | 出口标准 |
| --- | --- | --- |
| **M0 脚手架** | 仓库、文档、合同、双半包骨架、CI | `node --test` 绿；桌面端能装上一个「什么都不做」的插件 |
| **M1 Spike** | 关闭 [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md) 里全部 6 条 | 每条都有「实测 + 出处」结论，写回 RESEARCH/ARCHITECTURE |
| **M2 竖切** | 一条端到端最薄通路：轮次结束 → 辅助请求 → 路由 → 建议条 → 采纳写入 | 手工矩阵通过；失败路径全部静默 |
| **M3 打磨** | 配置卡、i18n、节流与成本上限、无建议时的克制、无障碍 | 配置项全覆盖单测；设置卡可存读 |
| **M4 发布** | CHANGELOG、版本号、npm + GitHub、桌面端可更新 | 全新机器按 README 装得上、更得动 |

## 4. 验收（MVP）

1. 装好后随便聊一轮，输入框上方出现一条中文建议；点它，草稿里多出这句话，光标在句末。
2. 建议出现时不打断输入；用户一开始打字，建议立刻消失。
3. 断网 / 模型 429 / 路由缺失：**看不到建议，也看不到报错弹窗**；日志里有一条 warn。
4. 关掉插件开关：DOM 里不残留任何节点，也不再有后台请求。
5. 会话 A 的建议不会出现在会话 B。

## 5. 与官方的关系

本插件是**宿主外挂**：官方发布新版本时，我们只跟随它的 client 服务名与 seam 变化，不要求官方为我们改一行代码。反过来，如果官方哪天内置了该能力（很可能），本插件应当能被干净地停用 —— 所以任何实现都不得假设「只有我能写输入框」。
